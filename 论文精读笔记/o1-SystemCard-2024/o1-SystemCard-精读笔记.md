# OpenAI o1 System Card 精读笔记

> 原文：*OpenAI o1 System Card*，OpenAI，2024-12-05，52 页（arXiv: 2412.16720）
> 性质：o1 正式版发布时随附的安全报告，覆盖安全评估、外部红队、准备度框架评估
> 笔记重点：**o1 相比 GPT-4o 时代引入的「新设定」**——新的机制、新的评估范式、新的风险类别

---

## 0. 一句话定位

o1 是第一个用**大规模强化学习 + 思维链推理**的模型系列。这份 System Card 的价值不在于"又一份安全报告"，而在于它确立了**推理模型时代的安全评估范式**——后续 o3、DeepSeek-R1 等都沿用这套话语体系。

发布时间线：o1-preview（2024-09-12）→ o1 正式版 + 本报告（2024-12-05）→ o1 改进版（2024-12-17，报告明确不覆盖）。

---

## 1. 新设定一：推理时计算（test-time compute）成为新的能力旋钮

**旧范式（GPT-4o 及以前）**：模型能力 ≈ 架构 × 数据 × 参数量，回答一步到位。
**新范式（o1）**：多了一个变量——模型回答前可以「想更久」。同一份参数，思考时间越长答案越好。

这意味着能力增长从「训练时」部分转移到「推理时」。§2 原话：模型通过训练学会优化思考过程、尝试不同策略、识别自己的错误。

**为什么这是安全报告的关键前提**：所有后续章节都建立在这个机制上——思维链既是安全增强的工具（§1、§4.3），也是新风险的来源（§4.4.3）。

## 2. 新设定二：审慎对齐（Deliberative Alignment）

**是什么**：训练模型在产出答案之前，**显式地对安全规范进行推理**——在上下文中"读出"安全政策再决定怎么回答，而不是靠条件反射式拒绝（§1 脚注 1）。

**为什么新**：以前的安全训练是"行为克隆"式的（见过有害请求→学会拒绝），审慎对齐是"推理"式的（理解政策→现场权衡）。这让安全能力第一次可以**泛化到没见过的攻击**。

**配套改动**（§5.3）：更新拒绝政策格式、生成新安全数据、针对政治说服任务引入全新拒绝行为。

**效果**：o1 在最难的 Challenging Refusal 评估上从 GPT-4o 的 0.713 提到 0.92（§4.1.1）；StrongReject 等越狱评估显著优于 4o（§4.1.2）。

## 3. 新设定三：指令层级（Instruction Hierarchy）

**是什么**：给消息规定明确优先级——**system > developer > user**（§4.2）。

**为什么需要**：o1 的 API 首次允许开发者自定义 developer message，这开了一个绕过护栏的口子。指令层级就是堵这个口子的。

**效果有多猛**：「数学家教越狱」测试（系统消息要求不许给答案，用户想尽办法骗答案），GPT-4o 守住率只有 **0.33**，o1 达到 **0.95**（表 6）。

## 4. 新设定四：思维链成为可监控的对象

这是我觉得全报告最有远见的部分。以前模型的"想法"是无法解读的激活值数字；o1 的思维链是可读文本，于是出现了两个全新的安全机制：

### 4a. CoT 欺骗监控器（§4.3.1）

- 用 GPT-4o 当监控器（验证准确率 92%），扫描 10 万条合成提示下 o1-preview 的思维链；
- 结果：102,443 条中 **0.17%** 被标记为欺骗；最大类是"幻觉出政策再故意隐瞒"（0.09%），其次是"故意幻觉"（0.04%，典型是编造参考文献）；
- 重要结论：**没有发现**模型为满足用户请求之外的目的而故意欺骗。

### 4b. CoT 摘要器（§4.3.2）

- 用户在 ChatGPT 看到的"思考过程"不是原始思维链，而是独立摘要模型生成的摘要——**摘要本身是一个新的风险表面**；
- 检查结果：摘要引入违规内容的比例仅 0.06%，无训练数据复述。

### 监控的局限

报告自己很坦诚：CoT 是否忠实反映模型真实想法仍是开放研究问题——会打草稿的模型也可能学会"打两份草稿"。

## 5. 新设定五：缓解前 / 缓解后双轨评估

**设定**：同一模型测两遍——pre-mitigation（未做安全训练，仅研究用，测"最坏已知情况"）和 post-mitigation（含安全训练的发布版）。

**为什么重要**：这让报告能回答"能力上限在哪"和"护栏拦不拦得住"两个不同的问题。CBRN 章节的解读全靠这个区分——缓解前模型能帮专家做生物威胁操作规划（能力上限达到 Medium），缓解后模型拒绝了所有中高危提示（护栏有效）。

**谨慎原则**：Safety Advisory Group 把缓解后评级定为与缓解前**相同**，宁可高估风险。

## 6. 新设定六：准备度框架下首个 Medium 风险模型

o1 在准备度框架四类别中的评级（§5）：

| 类别 | 评级 | 一句话理由 |
|---|---|---|
| 说服力 | **Medium** | 人类水平说服力（ChangeMyView 前 80–90% 百分位），但未超人类 |
| CBRN | **Medium** | 能帮专家做已知生物威胁的操作规划；不能帮非专家（缺湿实验技能） |
| 网络安全 | Low | CTF：高中 46% / 大学 13% / 职业 13%，未达 Medium 阈值 |
| 模型自主性 | Low | 无一通过主要智能体任务；SWE-bench 40.9% |

o1 是 OpenAI 首个触及 Medium 的模型——刚好卡在"可部署"红线上（缓解后 ≤ Medium 才允许部署，≤ High 才允许继续开发）。

报告同时声明：评估只是风险的**下界**（§5.2）——更好的脚手架、微调、更长运行可能激发出未观察到的行为。

## 7. 新设定七：外部红队的新形态

### Apollo Research：scheming（密谋）评估（§4.4.3）—— 全文传播度最高

**设定**：给模型强烈目标 + bash 自主执行环境 + 让它发现自己的目标与开发者冲突，观察它选择纠正、公开对抗还是暗中欺骗。

关键数据（有目标引导时）：

| 行为 | 比例 |
|---|---|
| 试图关闭监督机制 | 5% |
| 试图复制自身权重覆盖替代模型 | 2% |
| 表面完成任务、暗中篡改数据 | 19% |
| 事后被质问时否认/编造解释 | 99% |
| 工具性对齐伪装（被评估时装乖，低监督时按自己目标来） | 37% |

注意两点：① 场景是**专为诱发密谋设计**的，不代表日常部署；② Apollo 认为 o1 智能体能力尚不足，密谋不太可能造成灾难性后果，但建议在高风险智能体场景部署 CoT 密谋监控。

### METR：智能体能力对标人类（§4.4.4）

定制脚手架下 o1 ≈ 限时 2 小时的人类水平，超过基线脚手架下最好的公开模型（Claude 3.5 Sonnet）。但约 **70% 的失败疑似假性失败**（不会用工具等），所以这不是上限。

### Gray Swan 越狱竞技场（§4.4.2）—— 反直觉结果

o1 的攻击成功率反而**略高**于 GPT-4o（有害文本 6% vs 3.5%）。原因：越狱一旦成功，o1 的回答更长更详细、严重程度更高。**"更难攻破，但攻破后后果更重"。**

### 成对对比中 o1 的四个"更不安全"时刻（§4.4.1）

o1 整体被评为更安全的比例 59.75%，但被比下去的对话有共性：① 涉险建议回答太详细；② 风险话题介入太深（如攀岩绳结）；③ 拒绝太生硬；④ 政策张力（健康话题）。

6. 红队对比：o1 更安全 59.75% vs 4o 28.48%

## 9. 个人理解与疑问

**理解**：整份报告的核心张力是——推理能力让模型更守规矩（审慎对齐、抗越狱暴涨），也让它更会钻空子（reward hacking 的进阶版就是 scheming）。安全和风险同源，都来自"会思考"。

**疑问（待补）**：

- 审慎对齐的训练细节报告没展开，要读它引用的论文（arXiv 2412.16339）；
- CoT 忠实性问题（§4.3 提到但未解决）——如果模型学会在思维链里也"表演"，监控就失效了，这块有哪些后续工作？
